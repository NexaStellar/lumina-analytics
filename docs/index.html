Current status

Early-stage backend prototype, not a production analytics product. The checked-in backend includes a Horizon service, a bounded Soroban RPC event service, a read-only REST API, and a health endpoint. There is no dashboard or persistent analytics database, and the Docker Compose setup is not a verified end-to-end deployment.

The REST API exposes selected Horizon reads, not a full historical archive. Do not rely on dashboard URLs, alerting, data export, persistent indexing, or complete Soroban event history as implemented functionality.

Architecture and scope

The backend contains HorizonService for Horizon reads and streams, SorobanService for bounded recent contract-event queries, and an Express bootstrap that mounts the read-only Horizon API under /api/v1.

Implemented nowHorizon queries and streams, bounded Soroban event queries, read-only REST endpoints, health checks, and mocked backend tests.
Configuration onlyCompose declarations for supporting services do not constitute a verified application deployment.
Not implementedDashboard, persistent analytics/indexing, WebSocket application server, alerts, data exports, and production operations.

Setup and known limitations

The backend requires Node.js 22.12 or newer. From backend/, install dependencies and run the checks:

npm ci
npm run lint
npm run typecheck
npm test -- --run
npm run build

Run npm run dev to start the API locally. It binds to 127.0.0.1:4000 by default. Tests use mocked Horizon and Soroban responses; they do not require live network access. The Compose setup is not a verified full application launch.

HorizonService uses Stellar Horizon. SorobanService is a separate read-only service that queries recent contract events through Soroban RPC.

Service and API patterns

Read-only HTTP endpoints

EndpointPurpose
GET /health, GET /api/v1/healthReturn backend health and network metadata.
GET /api/v1/statsReturn the recent Horizon network summary.
GET /api/v1/transactions/:hashLook up a transaction by its 64-character hexadecimal hash.
GET /api/v1/accounts/:publicKeyLook up a Stellar account by public key.
GET /api/v1/assets/:code/:issuerLook up an issued asset.
GET /api/v1/search?q=...Search supported account, transaction, or asset identifiers.

These are read-only endpoints. The API does not expose a dashboard or a complete event-history archive.

Call the API

curl http://127.0.0.1:4000/api/v1/stats

Fetch a transaction

import { HorizonService } from './services/horizon';

const horizon = new HorizonService(
  process.env.HORIZON_URL ?? 'https://horizon-testnet.stellar.org',
  'testnet',
);

const transaction = await horizon.getTransaction(transactionHash);
console.log(transaction.hash, transaction.successful);

Stream and close a subscription

const close = horizon.streamTransactions(
  'now',
  (transaction) => console.log(transaction.hash),
  (error) => console.error('Horizon stream failed', error),
);

// When stopping the consumer:
close();

Use the lookup helpers

const account = await horizon.getAccount(publicKey);
const page = await horizon.getRecentTransactions(25);
const results = await horizon.search(publicKey);

The service methods can also be called directly from backend code.

Configuration

HorizonService takes its endpoint and network as constructor parameters. The backend bootstrap reads the following environment variables:

VariablePurpose
API_HOST, API_PORTBind address and port; defaults to 127.0.0.1:4000.
NETWORKSelects testnet or mainnet metadata and the default Horizon URL.
HORIZON_URLOptional Horizon endpoint override; defaults to the selected network's public endpoint.
SOROBAN_RPC_URLOptional RPC endpoint used by SorobanService; defaults to Stellar testnet RPC.
DATABASE_URL, REDIS_URLIntended PostgreSQL and Redis connection strings; no checked-in code currently consumes them.
WS_PORTDeclared for a future stream server; no application WebSocket server currently binds it.

Use your own infrastructure credentials and avoid committing environment files. The Compose file includes development database credentials and must not be used as a production secret configuration.

Operational behavior and error handling

  • Horizon and Soroban RPC calls can fail due to connectivity, endpoint limits, invalid identifiers, or missing records; callers should surface upstream failures appropriately.
  • Pass the optional Horizon stream error callback and always call the returned close function when the consumer is finished.
  • getNetworkStats() computes average fee and success rate from up to 200 recent transactions; empty results produce zero values.
  • Horizon pagination is limited to integer page sizes from 1 through 200. Soroban event queries are also bounded and limited to the configured RPC node's retention window.
  • The API is a prototype. Review deployment security, rate limits, and operational monitoring before exposing it publicly.
